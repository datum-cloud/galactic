## Findings

| Finding                            | Status | Resolution                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F01 Disable after a failed refresh | Fixed  | `egressGroup.refresh` returns `Refresh`'s error. Leaving hashed mode publishes every enabled group as `CLOSING` (forwarding, but CNI ADD writes no new sentinel), then converts, and disables only after a conversion that read and wrote every route without error and found no sentinel left, foreign-namespace sentinels included. CNI ADD re-reads the groups after writing its routes and rewrites them in ordered mode if they closed meanwhile, which closes the race with concurrent registration.                                                                                                                                                                                               |
| F04 Pool compatibility             | Fixed  | One shard group per translation class: NAT66 for `::/0`, one per NAT64 prefix (at most three in hashed mode; more is a startup error). A shard joins a class's group only if its status can translate it (IPv6 address; or IPv4 address and that `nat64Prefix`, or `translatesWellKnownPrefix` for `64:ff9b::/96`). Every sweep recomputes eligibility, so a shard that changes leaves. Ineligible shards are logged and exported (`pool_members{state="ineligible"}`); a class no shard serves gets no route and `GalacticEgressClassUnserved`. Single-family clusters keep working.                                                                                                                    |
| F05 Generation uniqueness          | Fixed  | Superseded by the F06 design: a group is published as one snapshot in one atomic swap, so a slot that failed to publish was never visible to a packet. Generations come from `next_slot_generation` in the published snapshot plus an in-process high-water mark that also counts failed publications; disable keeps the counter, restart resumes from it, 0 is never handed out. The review's A→B(failed)→C sequence is reproduced against the kernel at each of the three publication steps.                                                                                                                                                                                                           |
| F06 Coherent BPF publication       | Fixed  | `egress_shard_group_table` and `egress_shard_table` (ARRAY maps updated in place) replaced by `egress_shard_groups`, an `ARRAY_OF_MAPS` whose slot holds one immutable snapshot: Maglev table and every member's SID, next hop, flags and generation. Publication creates a new inner map, fills it and swaps the outer slot in one update (an RCU pointer replacement; the old snapshot is freed after readers finish). The packet path reads everything from that one snapshot; one extra map lookup per grouped packet. The finding was confirmed on a kernel before the fix: updating a published value in place produced 17 torn packets out of 54,777; the snapshot swap produced 0 out of 49,011. |
| F02 Drain verification             | Fixed  | `verify-nat-active-active.sh` rewritten. Every probe requires every request to succeed, the capture to see every probe, and every source to be an expected masquerade address; silence fails. Fresh, never-pinned tenant addresses are added inside the tenant's network namespace, so drain and failure are checked under default pins. A self-test blackholes a fresh tenant and requires the probe to fail. Background downloads propagate failures; cleanup restores the environment, drain flags, ClusterRole, routes and addresses it found.                                                                                                                                                       |
| F03 Drain lifecycle documentation  | Fixed  | Docs and the new rollout checklist say: `spec.drain: true`, wait for sessions to end, then delete; deletion tears the shard down at once; a busy tenant can keep a shard draining indefinitely; pins off cannot preserve sessions. A terminating `EgressShard` is now excluded from the groups rather than treated as draining. No finalizer was added.                                                                                                                                                                                                                                                                                                                                                  |

## Compatibility

- **Map layout.** The two pre-review group maps are gone; `egress_shard_groups`
  and `egress_shard_group_template` are new. No map that existed before the
  feature changes, so an upgrade from a release without it keeps every pinned
  row. A node that ran a pre-review build of this branch (only the
  containerlab lab) has the two obsolete pins removed at load; its groups are
  rebuilt by the next sweep, and until then a route naming a group drops.
- **Rollback.** Unchanged in principle and now observable: switch to ordered
  mode, wait for `galactic_cni_egress_group_routes` to read 0 on every node,
  then roll back the image.
- **Older clang.** `egress_shard_group_template` exists because clang before
  21 emits the inner map value as a forward declaration. Generation was
  checked with clang-18 (CI's compiler) and clang-19 (the image builder's).

## Risks

- One extra map lookup per grouped packet, and a new inner map per change to
  a group (about 2.4 KiB, freed after RCU); a flapping shard costs a
  publication per change.
- A busy tenant keeps a draining shard in use indefinitely; draining needs an
  operator decision on how long to wait.
- The cause of the one unreproduced drain-stage lab failure is unknown.

| Finding                                                    | Status        | Notes                                                                                                                                                                                                                                                                                                                                                                                         |

| R01 Closing does not exclude in-flight CNI writes          | Partial       | CNI ADD re-reads the groups after writing and rewrites its routes in ordered mode if they closed. Every ordered-mode sweep also moves any route still naming a group back to the static list, so a late write is repaired within one sweep (30s), dropping that VRF's egress meanwhile. There is no cross-process barrier, so `group_routes` reading 0 can precede such a write by one sweep. |
| R02 Empty hashed membership restores static shard routes   | Open          | With no class served, a hashed sweep refreshes without groups and moves routes back to the first resolvable static SID, bypassing readiness and translation checks.                                                                                                                                                                                                                           |
| R03 Unserved NAT64 prefix falls through to the NAT66 route | Open          | CNI ADD skips a configured NAT64 prefix with no eligible shard, so longest-prefix match sends it to the NAT66 group's `::/0` route.                                                                                                                                                                                                                                                           |
| R04 Fresh-address counter lost in subshells                | Fixed         | The counter is kept in a state file, and a failed address add ends the run.                                                                                                                                                                                                                                                                                                                   |
| R05 Group IDs reused when the prefix list changes          | Open          | Group IDs are positions in `GALACTIC_CNI_NAT64_PREFIX`; removing or reordering a prefix republishes a group that existing routes still name for a different class.                                                                                                                                                                                                                            |
| R06 BGP stage withdraws only one route source              | Not borne out | The stage removes only the FRR origination, and the shard was reported unreachable within about 2s on every passing run: the compute resolver did not resolve the SID through the EVPN plain route. The stage does not separately assert the compute FIB lookup.                                                                                                                              |

R02, R03 and R05 affect hashed mode only and block enabling it; ordered mode,
the default, does not read the groups.
