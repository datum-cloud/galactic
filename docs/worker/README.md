# Galactic Worker

Galactic Worker is a node-local service. Service agents use it to
deliver tenant traffic locally or across the fabric, and it becomes the single
writer of shared host state. These pages are the contract for
[epic #1430](https://github.com/datum-cloud/galactic/issues/1430). Every Task of
the epic implements against them on the `integration/galactic-worker` branch.

Status: the service API, reconciliation core, client library and module
interface are implemented by
[#1433](https://github.com/datum-cloud/galactic/issues/1433). The Fabric module
([#1436](https://github.com/datum-cloud/galactic/issues/1436)) serves
`fabric.srv6` and `fabric.routes`, and is the only writer of the tenant routes
of every VPC Worker owns. The Local module
([#1435](https://github.com/datum-cloud/galactic/issues/1435)) serves the
`local.*` capabilities, and
[#1437](https://github.com/datum-cloud/galactic/issues/1437) resolves shard
destinations and lets a VPC's tenants egress through their node's own NAT
shard ([Local NAT shards](contract.md#local-nat-shards)).
[#1438](https://github.com/datum-cloud/galactic/issues/1438) resolves backend
destinations, so the gateway hands a backend on its own node to the backend's
TAP instead of encapsulating toward it
([Local handoff](../gateway/architecture.md#local-handoff)).

[#1439](https://github.com/datum-cloud/galactic/issues/1439) moves the Envoy
sidecar onto Worker: the galactic-vrf sidecar holds a `local.socket` claim per
VPC, and Worker publishes the return advertisement for the claim's addresses
([Envoy and the galactic-vrf sidecar](contract.md#envoy-and-the-galactic-vrf-sidecar)).
`examples/worker-client` is an independent client of the published API.
[#1434](https://github.com/datum-cloud/galactic/issues/1434) makes Worker the
owner of each node and VPC scope, with CNI writing that state under the fence
([ownership](ownership.md#node-and-vpc-scope)).
[#1440](https://github.com/datum-cloud/galactic/issues/1440) makes
galactic-edge, run with `--worker-socket`, claim its edge links from Worker
([connector](connector.md)).
[#1441](https://github.com/datum-cloud/galactic/issues/1441) packages Worker
for dedicated and combined placement, adds its operator diagnostics and the
handback that returns its scopes ([operations](operations.md)).

### Preconditions for the gateway's Local handoff

A gateway hands backends on its own node to their TAPs only with
`GALACTIC_GATEWAY_WORKER_SOCKET` set, `GALACTIC_GATEWAY_XDP_ATTACH=dispatch`, and
`GALACTIC_GATEWAY_BACKEND_HEALTH=true` on every gateway in its namespace (D48).
Backend health is what takes a backend whose handoff is not ready out of every
gateway's Maglev table (D45). Without it, that backend's flows through its own
node's gateway are dropped while other gateways keep selecting it.
