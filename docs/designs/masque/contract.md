# MASQUE connector contract

This is the implementation design for [#972](https://github.com/datum-cloud/galactic/issues/972), part of [MASQUE Connector for gVPC (#970)](https://github.com/datum-cloud/galactic/issues/970). It supersedes the [older gateway proposal](../masque-gateway.md) for this milestone. Decisions here are requirements for the follow-on issues, not claims that the service is implemented or qualified. The [acceptance matrix](acceptance.md) names their owners and evidence gates.

The [Galactic Edge contract](../../edge/provider-contract.md) owns attachment admission, host networking, fencing, prefix arbitration, publication and gVPC policy. MASQUE owns credentials, connector allocations, session generations and transport. The service uses CONNECT-IP over HTTP/3 on UDP/443 and HTTP/2 over TLS on TCP/443. Both enter the same admission and packet adapter. Public APIs, portal/plugin integration, product-client changes and production rollout are outside this design.

## Identity and resource mapping

A connector is an authority-issued UUID bound immutably to a VPC UID and a cell. Names, user-selected VPC headers, credentials and IP addresses are not identities. Deleting and recreating a VPC cannot preserve the binding. Moving a connector to another VPC or cell requires a new identity and explicit allocation; there is no cross-cell claim store.

**Use one EdgeService per connector authorization incarnation.** This deliberately gives each connector its own deadline and attachment, so another connector renewing the shared instance cannot keep it alive. A new authorization incarnation gets a new service name and UID. A refresh of the same credential revision within a running session may extend its current service only after trusted revalidation; credential rotation retires the old service incarnation and uses the release/recreate procedure below; a handoff to another provider pod uses a new service incarnation and the replacement procedure below.

| Object               | Identity and owner                                                                                                            | Cardinality                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| EdgeProvider         | Operator-approved provider name; record its UID in authority configuration; fixed ServiceAccounts and capability versions     | One registered MASQUE provider per cell                           |
| Connector allocation | Authority-owned immutable record UID, connector UUID, VPC UID, cell, /96 and attachment pool                                  | One retained record per connector                                 |
| EdgeService          | Authority-owned name derived from connector UUID and authorization incarnation; immutable VPC UID/provider; finite validUntil | One current grant per connector; retired grants are never renewed |
| EdgeInstance / Lease | provider.InstanceName(pod UID); Lease UID is its incarnation; new process holder ID on restart                                | One pair per provider pod, shared by that pod's connectors        |
| EdgeAttachment       | provider.AttachmentName(pod UID, service UID); pin object UID, service UID, VPC UID and instance                              | One per pod/service                                               |
| EdgeRoute            | Stable provider-wide hash of VPC UID and masked /96; pin route UID and accepted epoch                                         | One contended aggregate route per delegated /96                   |
| Local session        | Process boot ID, connector UUID and monotonically increasing session generation                                               | At most one forwarding session per connector                      |

The route name follows the [reference provider](../../../examples/edge-provider/README.md#route-names). Never derive it from a session, service incarnation or transport: contenders must address the same object. The accepted route holder, its attachment UID and Lease incarnation/epoch must match before packet I/O starts. A successful claim write, Ready or a cached Accepted condition alone is insufficient.

The service grants only its connector's /96 and `PacketAccess`/`PrefixReachability`. Its distinct attachment client pool is not delegated to the client. Core owns attachment address allocation in `EdgeService.status.allocations`; that is not the connector allocation database. Core alone writes BGPAdvertisements and the route index. MASQUE never accesses host maps, invokes hostattach, creates host VRFs, or operates a second route publisher or ownership lease store.

## Authority and durable allocations

The initial deployment uses existing Kubernetes Secret and ConfigMap kinds as internal storage, not new public CRDs. A separate **MASQUE grant authority** runs under an authority ServiceAccount. It validates operator-approved grants and writes EdgeServices. It has no provider token and no host access. The internet-facing provider cannot write EdgeServices, allocation records, grants or trust configuration. This authority is a MASQUE client-authorization component, not another attachment controller.

The operator owns one internal grant record per connector: immutable connector UUID, VPC namespace/name/UID, cell, credential digest, credential expiry, enabled flag, allowed gVPC destination prefixes and policy references. The opaque bearer credential is 32 cryptographically random bytes, base64url encoded; only its SHA-256 digest is stored in the authority's restricted Secret. Compare digests in constant time. Credentials have a maximum 24-hour lifetime, no default unlimited lifetime, and are never written to logs or metrics. Rotation installs a new credential revision; an old credential cannot open a new session after rotation. Existing sessions are revalidated against the current revision and close. A request using the new credential gets a new service incarnation after retirement of the old one; it cannot extend the old session's ceiling.

The provider sends credentials to this authority over an internal authenticated TLS channel. This is a private MASQUE interface delivered by [#977](https://github.com/datum-cloud/galactic/issues/977): `Authorize` takes the credential, requested VPC selector, authenticated pod UID and request nonce; `Refresh` takes the resulting authorization ID, credential revision and service UID; `Retire` conditionally ends that authorization ID. A successful response returns connector/allocation IDs, VPC UID, service namespace/name/UID, /96, allowed destinations, credential revision and absolute deadline. Invalid credentials return unauthenticated, wrong VPC or retired revision returns forbidden, and unavailable/stale authority returns retryable unavailable without a grant. Refresh never accepts a new credential revision implicitly. The authority validates every call against current records and binds authorization IDs to the calling pod; retries with the same nonce cannot create a second incarnation. Revocation notifications carry the authorization ID and revision and may accelerate closure, but delivery is not the safety backstop. The authority verifies the provider's pod-bound identity and uses uncached API reads of the grant and VPC; a caller-supplied VPC is only a selector that must match. Trust roots and server identity are operator-mounted, rotated with a bounded overlap of 24 hours; unknown or expired roots fail closed. TLS session resumption does not bypass a fresh admission decision. Neither the provider nor the client chooses its prefix, service, attachment identity or allowed destinations.

The allocator holds one ConfigMap ledger per VPC/cell, at most 256 entries and 256 KiB. Entries contain connector UUID, allocation UUID, /96, distinct attachment /120 pool, creation time and retired state. Every insert or retirement uses the ledger UID and resourceVersion as preconditions. Concurrent allocations conflict and retry from a fresh read; a lost reply is resolved by reading the connector's allocation UUID. The ledger is authoritative even when no EdgeRoute exists. It is writable only by the authority; providers receive immutable allocation snapshots. A missing/recreated ledger is an operator recovery event: refuse allocation and restore from backup, never infer free space from absent routes. Reaching the ledger limit refuses new connectors; sharding is future design work.

Retain an allocation until explicit operator retirement, across disconnects, credential rotation, expiration, pod restart and HTTP/2 fallback. Retirement revokes the grant and waits for the route to be released and its old gates fenced. For this milestone, retired /96s and attachment pools remain tombstoned and are **never reassigned** within that VPC/cell. This avoids an arbitrary time-based claim that delayed traffic has disappeared. Restore the ledger and grants together; rollback must not reuse allocation identities or credential revisions.

### Address plan

Follow the [gVPC tenant addressing plan](https://github.com/datum-cloud/enhancements/blob/main/architecture/design/network/addressing/tenant.md): a /48 per ULA VPC, regional /64 space, and a /96 per endpoint. Within the cell's regional /64, the authority reserves a connector /80 and a separate attachment /80 through the platform's existing allocation authority. These are reserved address ranges, **not overlapping workload VPCAttachment podSubnet objects**: Edge rejects a delegated route overlapping a workload subnet. Neither the MASQUE provider nor this ledger allocates a VPC /48 or silently carves space out of an existing workload subnet.

For example, for VPC `fd20:a1b:2c3d::/48`, reserve `fd20:a1b:2c3d:10:1::/80` for connector /96s and `fd20:a1b:2c3d:10:2::/80` for attachment pools within regional `fd20:a1b:2c3d:10::/64`. A connector can receive `fd20:a1b:2c3d:10:1:1::/96` and attachment pool `fd20:a1b:2c3d:10:2::100/120`. Its service grants the /96 and uses that /120 as clientPool. The pool lies outside every delegated /96, so no route contains an attachment's own address. Pools are distinct across connectors. A replacement reuses its retained pool only after the old service's attachments are released and the service is deleted; no two services hold it concurrently.

Assign the /96 through CONNECT-IP address assignment. Clients may use its primary address or subdivide it locally without adding routes to core. Advertise only the aggregate /96. The client may not request routes beyond the authority's destination allowlist. Reject IPv4 for this milestone on both transports and in both packet directions; do not silently accept it into an IPv6-only return demultiplexer.

## Client deadlines and revocation

The authority renews each active connector's service every 5 s after a fresh grant read. It timestamps the **start** of that read and computes:

```text
validUntil = min(credential expiry,
                 grant read-start wall time + 30 s - 2 s issuer clock allowance)
```

The response includes this absolute deadline, grant revision, service UID and allocation identity. A retry retains the original deadline; it cannot turn a delayed result into fresh authority. Requests have a 2 s API deadline and stale work is discarded. Service updates use UID/resourceVersion preconditions; retired authorization incarnations are never recreated or renewed by queued work. A new authority leader rereads all inputs before issuing anything. A provider never receives credentials capable of extending its own service.

Operator revocation is a committed disabled/rotated grant revision. Stop refreshing that connector, shorten its service deadline to the past, and notify its active session. The provider closes its packet path promptly. If notification, API writes or a worker stall, the already-issued finite service ceiling is the backstop. Other connectors retain their own services and continue renewing the shared instance.

| Event                                            | Required bound                                                                            | Assumptions and enforcement                                                                                                    |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Instance renewal stops                           | 15.5 s holder-clock cutoff; 15.52 s real-time threshold                                   | Foundation kernel gate, including API/provider/agent stalls                                                                    |
| Connector credential expires                     | No packets after expiry + 1 s real time                                                   | Service ceiling no later than credential expiry; node subtracts MaxSkew; includes 500 ms foundation margin and drift allowance |
| Connector grant revoked or credential rotated    | No packets after committed revision + 31 s real time                                      | Issuer read-start TTL above; uncached linearizable read, issuer/node wall error at most 2 s, monotonic drift at most 0.001     |
| Revocation with all components connected         | 2 s target                                                                                | Authority notification and service revocation; measured, not a guarantee                                                       |
| Authority or its grant store becomes unavailable | No new admissions; existing grants expire within 31 s of their last successful read-start | Never refresh from cached grants; unrelated grants survive only while independently revalidated                                |
| Local route withdrawal                           | Within 1 s of gate expiry while router runs                                               | Foundation map polling, independent of API                                                                                     |
| Router dies                                      | Reflector withdrawal within 9 s of router loss                                            | Negotiated hold time at most 9 s, configured on both ends                                                                      |
| Remote convergence                               | 5 s target after local withdrawal                                                         | Measured separately; stale remote paths still meet a closed old gate                                                           |

The 31 s connector bound is additional to, not a replacement for, the foundation's 15.52 s instance/revocation thresholds. A grant read that races revocation can issue at most its original 30 s window: subtracting the issuer's 2 s allowance prevents a fast issuer clock extending that window. Node ceiling conversion subtracts its own MaxSkew; 31 s leaves room for 500 ms margin and monotonic drift. Finite credential expiry is an absolute trusted timestamp, not a provider-supplied duration. Clock excursions outside these assumptions require admission to stop; no real-time guarantee is claimed for a VM whose clock stops during pause/live migration. Use the foundation's physical-node or no-pause deployment assumption.

Never set the shared instance lease ceiling from one connector's credential: the per-service gate ceiling is what isolates its expiration from its neighbors.

The existing implementation mechanism is `EdgeService.spec.validUntil` and [the agent's per-route ceiling](../../../internal/edge/agent/gate.go); `TestGateCeiling` covers the primitive. The **multiple connectors sharing a live instance** scenario remains a required integration check. No foundation extension is selected by this design. If refresh, service replacement or ceiling qualification cannot meet these requirements, [#976](https://github.com/datum-cloud/galactic/issues/976) must track a foundation change under [#992](https://github.com/datum-cloud/galactic/issues/992) and qualify it before integrated acceptance. Falling back to cancellation-only expiry or sharing one uncapped service is forbidden.

## Interfaces and session transitions

Use the existing [connectip interfaces](../../../internal/edge/connectip/backend.go): `Admission.Admit`, `Lease.Info/Routes/Done/Close`, and `PacketBackend.Open`. [`internal/edge/masque`](../../edge/masque-provider.md) implements them over the provider contract. `SessionInfo.ID` is the request generation, `Connector` is the connector UUID, `VPC` carries the immutable VPC identity, and `Epoch` is the Edge route epoch. Do not overload one epoch for both session and foundation authority. The adapter keeps the full attachment/service/route UIDs, instance incarnation/epoch and process boot ID beside this snapshot; string names alone cannot authorize I/O.

1. **Pending:** reserve bounded pre-admission capacity before credential parsing or API work. Authenticate and authorize with the authority. No TUN write or MTU probe yet.
2. **Allocated:** read the retained /96 and finite service grant; reserve one connector session transition. A failed admission releases provisional request resources, not the durable allocation.
3. **Attached:** obtain the pod's shared instance lease through `internal/edge/provider`; request the derived attachment and verify its immutable references. Wait for Programmed, open only the device named in status, then set Ready.
4. **Claiming:** contend for the stable EdgeRoute. Wait for the accepted holder/epochs and observed open gate/local publication for that exact incarnation. Provider Ready is not permission to forward.
5. **Active:** install the current generation in the packet adapter, then accept CONNECT-IP and perform any authenticated MTU probe. Check authority, generation, IPv6 source ownership and destination allowance at every I/O boundary, including dequeue. Return traffic is scoped by attachment/VPC identity before destination /96 lookup.
6. **Closing:** mark generation closed, unblock and drain its I/O, discard its buffers, then conditionally release only the claim epoch it still owns. A stale Close is a no-op for its successor. Release an attachment only when no active/provisional session reference remains; release the instance only when the pod drains all its connectors.

The packet adapter accepts only complete IPv6 packets within the device MTU, walks at most 8 extension headers and 256 extension-header bytes, and rejects fragments (including atomic fragments), malformed lengths and unevaluable policy with a counted reason. This milestone does not promise fragmented-inner-packet support. Required ICMPv6 errors and control traffic follow the foundation policy and CONNECT-IP rules; locally generated errors are associated with the same tenant/session and cannot bypass destination/source checks. [#979](https://github.com/datum-cloud/galactic/issues/979) tests this profile against the pinned library.

Do not hold a shared lock across an API call, blocking packet write or queue wait. One renewal worker owns the pod's one instance lease; route acquisition/release cannot hold its mutex. Separate bounded control/renewal workers from transport workers. Request cancellation must cancel its own work without cancelling another connector's renewal.

### Same-instance replacement

A per-connector transition lock admits one replacement at a time; a concurrent loser receives a retryable conflict. Authenticate the replacement before disturbing the active session. Allocate a new process-local generation, mark the predecessor closed, prevent new writes, cancel and join its workers, discard its queued packets and flush the packet reader's pending delivery before activating the replacement. Packets already queued in userspace carry their arrival generation and cannot be relabeled. If an old worker cannot quiesce within 1 s, fail the replacement and revoke this connector's service; never activate a second writer beside it. A process restart uses a fresh boot ID and the foundation instance takeover rules.

The same attachment and EdgeRoute can remain held during a successful same-process transition, but the I/O barrier must finish before the successor becomes Active. Cancellation, release and callbacks compare the entire generation/UID tuple. An old callback cannot delete the successor's registration, close its device or release its claim. Incoming packets read after the barrier belong to the current retained address; IP itself has no session generation, so this does not promise to identify an old packet delayed in the remote network. Transport sequence state and already-buffered application bytes are never transferred.

HTTP/3-to-HTTP/2 fallback is a newly authenticated CONNECT-IP request using this exact procedure. It retains the /96 but not the QUIC connection or a lossless packet stream. Inner flows may survive if endpoints tolerate the interruption; session continuity is not guaranteed.

### Cross-instance replacement and stale cleanup

A replacement cannot force transfer from a live holder merely by writing a higher route epoch. Ask the authority to retire the old connector service, stop refreshing it, and drain/delete its attachments. Persist this transition in the connector's authority record with UID/resourceVersion preconditions so concurrent replacements choose one successor. Keep the allocation reserved throughout.

Wait for core's fencing evidence and old attachment release, then delete the old service and create the successor service with the same allocation/pool and a new incarnation. Refresh only the successor. The new pod requests its own attachment and takes the **same** EdgeRoute through core's acceptance. In particular, do not refresh the old service to make a new claimant ready: that could reopen the old holder. The old instance may continue renewing for unrelated connectors; revoking its service closes only this connector's gates.

If the old node cannot report Released, replacement waits. No bounded availability is promised for that case, even after packets are proven stopped. This is the deliberate cost of reusing the retained attachment pool without bypassing foundation cleanup. Core's cross-attachment acceptance still requires confirmed old closure or the 15.53 s TakeoverWait and its fencing rules; MASQUE cannot substitute a timer or its own lease. API partition with client/gVPC connectivity intact must produce packet cutoff, not dual forwarding.

Late cleanup uses UID, route epoch and session generation preconditions and cannot remove a replacement's objects. After a restart, reconcile from authority/API state and reacquire; do not restore forwarding permission from a local cache. Fencing state stays in the foundation's node directory for the host lifetime, and MASQUE never deletes it. Router GC and CNI maintenance remain foundation responsibilities.

## Deployment and test provisioning

Request `v1alpha1`, `PacketAccess/v1` and `PrefixReachability/v1`. Reject unsupported capabilities before allocation. Use a pod-bound ServiceAccount token with the API audience and the foundation's admission policies; verify the Kubernetes token extras required by that contract. The provider gets no hostNetwork, hostPID, hostPath, NET_ADMIN or BPF privileges. A device plugin supplies `/dev/net/tun`; core creates the TUN in the pod namespace. Bindings grant only provider-owned resources/Ready, not service grants, accepted status, route indexes or BGPAdvertisements.

The operator provisions the VPC, address reservations, policies in both directions, approved EdgeProvider, authority ledger/grant Secrets, and TLS trust. The authority's access to tenant namespaces is explicitly scoped by RoleBindings; registration alone grants no tenant authority. The provider receives service namespace/name/UID and VPC UID through the authenticated authority response, not broad tenant read access. Deny service/status and privilege-escalating writes in negative RBAC tests.

For authorized test connectors, an operator tool delivered by [#977](https://github.com/datum-cloud/galactic/issues/977) creates the ledger entry and a restricted grant Secret, emits the random bearer once to the test runner, and records only its digest. It validates the selected VPC UID and reserved pools. The authority creates the finite EdgeService; the runner supplies the bearer and VPC selector to an independent CONNECT-IP client. Revocation disables that grant; cleanup waits for Released and asserts removal of test host links, gates and routes while retaining/tombstoning the allocation according to policy. No portal, public enrollment endpoint or provider-minted EdgeService is needed.

Startup requires the foundation components, device plugin and an existing canonical host VRF (a workload of the VPC on each provider node, as the current contract requires). Until policy, attachment and exact route incarnation are ready, refuse traffic. Rollout first qualifies compatible core artifacts, then authority, then providers. SIGTERM stops admission, closes sessions and releases their route epochs and attachments, and finally releases the instance. Graceful drain has a 30 s budget; security deadlines always take precedence. Provider crash, core/node restart, API outage and delayed cleanup are tested separately.

## Resource budgets and benchmark contract

These are initial **qualification targets**, not measured capacity. [#984](https://github.com/datum-cloud/galactic/issues/984) must publish results for HTTP/3 and HTTP/2 separately and obtain review of any target change before closure. Both transports use identical session/foundation limits.

| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider size             | 4 dedicated CPU cores, 8 GiB memory allocation; provider RSS at most 1 GiB and average CPU at most 3.2 cores at target load                                                                                          |
| Active connectors         | 32 per pod; 128 per cell across 4 pods; at most 256 retained allocations per VPC/cell                                                                                                                                |
| Replacement headroom      | At most 32 additional closing/provisional sessions per pod; 256 total attachments and 8 instances during a cell roll                                                                                                 |

| HTTP/3 throughput         | At least 250 Mbit/s aggregate bidirectional inner-IP goodput per pod                                                                                                                                                 |
| HTTP/2 throughput         | At least 100 Mbit/s aggregate bidirectional inner-IP goodput per pod                                                                                                                                                 |

Benchmark on two physical edge nodes and a separate client/load host connected at 10 Gbit/s, with a local workload and a workload on a remote node. Pin OS/kernel, Talos/Cilium, CPU model, NIC/MTU, core/provider images, library and client versions. Run each transport with 1, 8 and 32 connectors per pod and 128 per cell; include two tenants deliberately sharing inner address values. Use 1280-byte inner IPv6 packets for throughput, a separate 64-byte packet-rate run, and a 50/50 byte split between UDP and TCP, evenly in both directions. Warm up 2 minutes and measure 10 minutes, three runs each. Report all runs, p50/p99 RTT, loss, CPU, RSS, queue peaks, API requests/status fanout and map occupancy. Throughput thresholds apply to the loss-free baseline; require less than 1% UDP loss and p99 added RTT at most 10 ms above the untunneled path.

Repeat with 1% packet loss, 50 ms added RTT, 10 reconnects/s, stalled readers/devices, and offered load at twice every admission/session limit. Overload must reject bounded work, preserve expiry bounds, and keep existing unrelated sessions at at least 80% of their baseline goodput under admission floods. Queue/RSS caps continue to hold; queues and active session counts return to baseline within 30 s of load removal. Report process/core/API budgets separately; adding privileges or bypassing policy is not a performance optimization.

## Alternatives and consequences

A shared EdgeService per VPC would reduce attachment count and grant writes, but its deadline would cover every connector. Session cancellation alone cannot enforce individual expiry while a control worker is stalled. A new independently expiring per-route client grant could support shared attachments more efficiently, but would require a versioned foundation extension and fresh qualification under [#992](https://github.com/datum-cloud/galactic/issues/992). This design instead uses existing per-service ceilings, accepts the attachment/API overhead, and makes M05/M18 qualification gates explicit.

One instance lease per connector would separate failure domains but conflicts with the foundation's pod-bound instance identity; inventing another lease store would not make core honor it. Immediate cross-node pool reuse before Released would improve availability but bypass allocation cleanup. Retaining tombstones consumes ledger space deliberately; exhaustion refuses admission rather than risking address reassignment. The initial 128-connector capacity target includes those costs and does not imply that the foundation's 1024-route ceiling is a supported MASQUE throughput level.

## Protocol references and scope

[CONNECT-IP (RFC 9484)](https://datatracker.ietf.org/doc/html/rfc9484) defines the tunnel, address assignment and route advertisements. [RFC 9297](https://datatracker.ietf.org/doc/html/rfc9297) defines HTTP Datagrams and capsules: the HTTP/2 fallback carries datagrams in capsules on a new request. HTTP/3 uses [RFC 9114](https://datatracker.ietf.org/doc/html/rfc9114), [Extended CONNECT, RFC 9220](https://datatracker.ietf.org/doc/html/rfc9220), [QUIC DATAGRAM, RFC 9221](https://datatracker.ietf.org/doc/html/rfc9221), and [QUIC transport, RFC 9000](https://datatracker.ietf.org/doc/html/rfc9000). HTTP/2 uses [RFC 9113](https://datatracker.ietf.org/doc/html/rfc9113) and [Extended CONNECT, RFC 8441](https://datatracker.ietf.org/doc/html/rfc8441). TLS follows [RFC 8446](https://datatracker.ietf.org/doc/html/rfc8446) and QUIC's binding in [RFC 9001](https://datatracker.ietf.org/doc/html/rfc9001).

[#973](https://github.com/datum-cloud/galactic/issues/973) selects and proves libraries and independent clients; the [CONNECT-IP interoperability proof](../../edge/connectip-interop.md) records the selections, results and the work an HTTP/2 listener still needs. This contract does not assume HTTP/2 support in the current HTTP/3 server. [#982](https://github.com/datum-cloud/galactic/issues/982) must prove 1280-byte IPv6 packets in both directions and correct ICMPv6 Packet Too Big or explicit tunnel failure when the path cannot carry them. Packet-size claims include encapsulation overhead; an attachment MTU floor is not evidence of end-to-end MTU support.
