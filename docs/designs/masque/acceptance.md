# MASQUE acceptance and evidence matrix

This matrix accompanies the [connector contract](contract.md) for [#972](https://github.com/datum-cloud/galactic/issues/972). Every check below is a required deliverable, **not an executed result**. [#985](https://github.com/datum-cloud/galactic/issues/985) owns the final evidence index. A closed foundation issue or a passing controlled-backend protocol test does not qualify the integrated MASQUE service.

## Evidence rules

Each result records its row ID, exact command, test name, UTC date, commit and image digests, schema/manifests, client/library versions, lab host hardware, Kind/Cilium/Kubernetes/kernel versions, actual provider privileges, and pass/fail. Keep core, independent-provider and MASQUE artifact identities separate. Include the versions containing the fixes from [#1064](https://github.com/datum-cloud/galactic/issues/1064), [#1066](https://github.com/datum-cloud/galactic/issues/1066) and [#1067](https://github.com/datum-cloud/galactic/issues/1067) and rerun affected cases. Pin the tenant addressing reference revision used for provisioning. A failure or required skip blocks the row; readiness and mock-only tests are insufficient packet evidence. Where a row names a node reboot, restart the Kind node container. That restart shares the lab host's kernel, so it keeps the kernel boot ID and kernel-held state; it covers loss of the node's processes and container filesystem, not a new boot.

Packet cases use sequence-numbered traffic in both directions, capture at sender and all relevant receivers, and first prove a positive control. A denied packet must reach neither its workload nor another connector. Record attempted, delivered and denied counts, capture loss and clock uncertainty. Failure tests sample at most 20 ms apart and report the last delivered packet relative to the named trigger. Include uncertainty in the upper bound; do not add an undocumented tolerance to the pass threshold. Keep local cutoff, local BGP withdrawal, reflector withdrawal and remote convergence as separate measurements.

[#985](https://github.com/datum-cloud/galactic/issues/985) packages setup, fault injection, collection and cleanup commands in a clean-checkout fixture. It asserts removal of test-created links, routes, maps, namespaces and API resources and preservation of unrelated resources. The ledger's retained/tombstoned allocations are expected state, identified explicitly rather than called a leak. Cleanup errors fail the run. Tests never deploy to production as part of this milestone.

`task verify:masque-conformance`, run from `deploy/containerlab`, runs the [#974](https://github.com/datum-cloud/galactic/issues/974) packet-access checks on the lab's dfw cluster. It covers M16, M07, and the #989 findings A06, A14 and A16, plus NAT egress from the attachment node, two connectors sharing one attachment while one request ends, router garbage collection while connectors forward, a provider process killed and restarted in place, pod recreation, a partly set-up instance killed without shutdown, and asserted teardown. A14's namespace-only impostor is a real-kernel test of `internal/edge/hostattach`. The provider is the test-only fixture in `tests/edgeconformance/masqueprovider`. It runs the [MASQUE provider adapter](../../edge/masque-provider.md) with `internal/edge/connectip`, and admits static test credentials, or authorizes through the [#977](https://github.com/datum-cloud/galactic/issues/977) [grant authority](../../edge/masque-authority.md) when configured. MASQUE acceptance runs on the containerlab gvpc lab and on loopback harnesses; no row requires physical edge nodes or a target-platform run. [#985](https://github.com/datum-cloud/galactic/issues/985) owns running every row in this matrix on the lab.
